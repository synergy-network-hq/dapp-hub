# Atlas detail acceptance

Atlas detail selection follows the pinned Atlas owner at `3fb8f87`. The supported service routes are `GET /blocks/:id?includeTx=true`, `/txs/:hash`, `/address/:address`, `/validators/:address` and `/contracts/:address`. Their responses are checked against the selection's height and known block hash, typed transaction hash, normalized account or contract address, or nested `validator.address`. The validator endpoint can report setup-pending entries. The inspector preserves that reported status. The token registry and search result remain the available local token details because the owner has no single token detail GET. Browser destinations use the owner's fixed explorer pages under the existing external-links grant.

Selecting a new row aborts the prior detail read. List navigation, search, refresh, endpoint or permission changes clear pending and completed selections. Returning to a prior scope requires a new selection. Block rows accept the pinned snake-case list fields and the observed live camel-case projection.

Direct public HTTP spot checks on 2026-11-15 returned JSON for the block, transaction and validator lists and matching detail identities for one entry from each. Eleven isolated Portal component cases use injected transports for identity mismatch, local invalid-identifier refusal, selection races, page/tab/search/refresh changes, endpoint and permission changes, scope round trips, and external grant enforcement. The Atlas package build passed. These checks cover service reads and renderer state. Native transport cancellation and hosted browser navigation were not exercised.
