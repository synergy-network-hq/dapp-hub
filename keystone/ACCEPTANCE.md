# Keystone current acceptance

Existing proposal/table/detail/cards design is retained. Network observations use the existing bounded host governance scan and are labelled partial index evidence, not authoritative governance, finalized state or complete vote history. Source age is visible; missing/failed/loading data is not zero proposals. Selected records are resolved by unique current hash so missing/ambiguous records hide earlier details. Dates are bounded to valid Date conversion before formatting. The scan itself still needs stable cursor/schema and complete cross-context/native acceptance.

Removed the old guessed transaction envelope builder, including hard-coded bond/timing/gas, numeric nonce coercion, signature algorithm and WalletAction submission path. Vote/publish requires current owner policy/codec, approved phone/APQE proof, simulation and broadcast/finality reconciliation. No transaction request capability remains in the manifest. Explicit readWallet is declared and checked before account-specific indexed filtering; no existing grant is silently reused or created. Changed declared capabilities require reviewed consent under the existing host policy. All releases remain null.

Local proposal text uses the original title/summary input design. A separate version1 local-only title/summary record has64Ki-character read bound, bounded160/8000-character fields, strict supported shape, stale raw-baseline refusal and explicit saved-copy replacement. Unsupported originals remain untouched. No network/proposer/timing/bond/memo/transaction/signature authority is created. Legacy saved proposal formats remain at their original keys, unmodified. Synthetic storage smoke verified persistence, stale overwrite refusal and corrupt-original preservation; browser/storage-failure/native acceptance remains open. No deletion control or automatic publication/retry.
